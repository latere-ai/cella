# API

## Overview

One HTTP surface on the public listener under `/v1`, one grammar for
every kind: apply by name, read and act by id, list, delete, the
kind's verbs, and for a sandbox the streams into it. Every response
body is JSON, or YAML on request, except a stream. Every error is one
envelope with one code and one fixed user sentence, and this spec is
the table those sentences live in. The OpenAPI document is generated
from the Go types of every kind and served, so a client generator and
the server agree by construction.

## Current state

[[026-direct-control-plane]] implements the authenticated native Sandbox lifecycle and bounded synchronous execution subset. [[034-terminal-attach]] adds the exec and attach WebSockets with the frame protocol below. [[041-display-and-input]] adds the display, screenshot, screen and input routes with the port state, and the `Display` and `Input` gates. [[051-environments-and-workers]] adds `GET /v1/environments` and `GET /v1/environments/{id}`, the two key routes, and the two routes an environment key reaches on a worker's behalf; the apply and delete of the kind wait on environments as desired state. [[055-api-contract-gaps]] adds the apply route and its name rule, the framed `POST` exec stream, content negotiation over the whole surface, `GET /v1/events`, the dial route's capability gate, `GET /openapi.yaml` held to the mux by a test, and the request id of the rule below. [[060-dial-and-port-proxy]] serves the dial socket and the port proxy through the driver's `Dial`, and `upstream_unavailable`. This does not complete `If-Match`, the rate limit, the other streams or the remaining kinds.

Design provenance: The routes descend from the hosted platform's `/v1`, with
the manifest as the only create body and apply by name added.

## Design

### Addressing

Every kind is applied by name and addressed by id. `PUT
/v1/<kinds>/{name}` creates the caller's object of that name or
updates it; every other item route takes `{id}`, the prefixed ULID of
[[001-architecture]], and also accepts a name, resolved among the
objects whose `owner` is the caller's; for a workload caller, the
owner is its own `status.owner`, so a sandbox addresses its siblings
and children by name. A body whose `metadata.name` differs from the
path is `invalid_field` at `metadata.name`. `POST /v1/sandboxes` with a
name another live object of the caller's holds is `name_taken`;
without a name, `Resolve` generates one through `NewName`.

### Concurrency

Every object response carries `ETag: "<version>"` from the store. A
`PUT` may carry `If-Match` with that value; the handler resolves and
`Put`s with it, and a row that moved is 409 `version_conflict`. A
`PUT` without `If-Match` is a read-modify-write the handler retries up
to three times on a conflict before returning `version_conflict`, so a
caller that does not care about concurrency never sees one in
practice.

### Assembling Resolve

For every apply the handler builds `manifest.Options` as follows.
`Actor` is the rendered subject of [[006-identity]] and `Workload` is
true when the subject carries the `sandbox:` prefix. `Lookup` is
constructed per request over the store and the authorizer's decision
cache, asking `secret.mount`, `volume.attach`, and `environment.use`,
and mapping a deny to `not_found`. `Existing` is the caller's object
of that name when one exists. `Parent` is, for a workload caller applying a name none of the
owner's live objects holds, its own sandbox's desired spec and status,
loaded by the id in the subject; that apply is a spawn
([[022-mesh-and-spawn]]). A workload's `PUT` of an existing name is an
update with `Parent` nil. `Defaults` and
`Ceilings` are the operator's ([[007-admission]]); `Limits` carries
the authorizer's `max_priority` for this subject; `Admit` is the
configured admission function with an `AdmitRequest` carrying the
request id; `Now` is the clock; `NewName` is the API's generator. The
count ceiling is checked in the same transaction as the desired write
([[007-admission]]). The response is the resolved manifest with the
stored status merged in.

/.well-known/jwks.json` (the token key set) and `GET /openapi.yaml`.
Everything under `/v1` requires a bearer; the worker routes accept an
environment key and nothing else.

The handler order for every item route: read the object by id or
alias, build the authorizer's `resource` from it, authorize, act. A
missing object is `not_found`; a deny on the request's own action is
`forbidden`; a deny reached through `Lookup` at resolve is `not_found`
([[006-identity]]). `?owner=` and every other list selector are
intersected with the authorizer's `filter`, so a selector outside the
filter yields an empty list, never 403.

### The file routes

Every path is absolute and inside the sandbox's managed workspace
([[004-runtime-contract]]'s containment rule), and a route that takes one
path refuses a request that names it more than once with `invalid_field`.
An entry is
`{"name", "path", "size", "mode": "0644", "modTime", "isDir"}`; the mode
is octal text, because a JSON number for a permission set reads as
decimal and is misread. A listing answers `{"items": [entry...], "next":
""}`, whole: a workspace directory large enough to need a cursor is a
tar.

The two writes on the collection are told apart by the selector, not the
body: `dest` extracts an archive and is `unsupported_media_type` unless
the body is `application/x-tar`, `path` writes one file of any content
type, both together are `exclusive_fields`, and neither is
`invalid_field`. A caller therefore stores an archive as one file by
naming `path`.

| Refusal | Code |
|---|---|
| A path outside the workspace, through a link that leaves it, or named more than once; a listing of a file; a move onto a directory; a remove or a move of the workspace itself; a mode that is not octal text of at most `0777` | `invalid_field` |
| A path that names nothing | `not_found` |
| A body past `CELLA_MAX_UPLOAD_BYTES`, with the file the write named unchanged | `body_too_large` |
| A sandbox whose driver reaches the workspace only while it runs, stopped | `phase_conflict` |
| An environment whose driver declares no `Files` | `capability_unsupported` |

Each call stamps activity and writes one `sandbox.files` operation naming
the operation, the paths and the byte count ([[009-events]]).

### Capability gates

A route that needs a capability the sandbox's environment does not
declare is 422 `capability_unsupported` before any driver call:
`Attach` for the exec WebSocket and attach, `Dial` for dial,
`Snapshots` for the snapshot routes, `Display` for display,
screenshot, and screen, `Input` for input, `Files` for the archive
routes while the sandbox is `Stopped` and for every granular file route.

### Bodies and content types

Manifest bodies accept the types of [[003-manifest-contract]], are
capped at `CELLA_MAX_BODY_BYTES` (413 `body_too_large`), and any other
type is 415 `unsupported_media_type`. Tar uploads are capped at
`CELLA_MAX_UPLOAD_BYTES` (default `1Gi`). Every object response is the
resolved manifest with `status`, as JSON in the Go struct order the
OpenAPI document records, or as YAML when `Accept` names one of the
three YAML types; any other `Accept` that excludes JSON is 406
`not_acceptable`. A list response is `{"items": [...], "next": "<cursor
or empty>"}`.

### Streams

| Stream | Transport | Framing |
|---|---|---|
| exec (`POST`) | the HTTP response, `Content-Type: application/vnd.cella.exec-stream` | frames of one byte of channel (`1` stdout, `2` stderr, `3` exit, `4` error) plus a 4-byte big-endian length at most 1 MiB plus the payload; the exit frame carries the code as decimal text and closes the stream; the error frame carries an error envelope as JSON and closes it |
| exec (`GET`), attach | WebSocket, subprotocol `cella.exec.v1` | the first text frame is the JSON request (`command`, `env`, `workdir`, `cols`, `rows`, `timeout`); binary frames are bytes both ways; text frames after the first are `{"resize": {"cols", "rows"}}` from the client and `{"exit": n}` or `{"error": {...}}` from the server, each followed by a close with code 1000 or 1011 |
| dial | WebSocket, `cella.dial.v1` | binary frames are bytes both ways; a close code 1000 when the inside closes, 1011 on error with the error's code as the close reason; the dial runs after the upgrade, so a port nothing listens on is a 1011 `upstream_unavailable` and not a status |
| files | tar, `Content-Type: application/x-tar` | the whole body; an error after the first byte is a truncated tar and a trailer header `X-Cella-Error` when the transport allows |
| logs, events with `follow` | newline-delimited, `application/x-ndjson` for events and `text/plain` for logs | one line per record; the connection closes with the sandbox |
| screen | WebSocket, `cella.screen.v1` | binary frames are PNG, at `?fps=` up to 10 |
| gateway sync | WebSocket, `cella.egress.v1` | one JSON text message per line: `hello`, `snapshot`, `put`, `purge`, `ack`, `heartbeat`, `record` ([[018-egress-and-secrets]]) |
| worker operations | WebSocket, `cella.worker.v1` | frames of a 26-byte operation id, one byte of sub-stream (`0` control, `1` stdin, `2` stdout, `3` stderr, `4` bytes), and the payload; control frames are JSON operations, results, and heartbeats; a reconnect resumes from the store's unacknowledged claims ([[010-state]]) |

The `POST` exec with `?wait=1` returns `{"exitCode": n, "stdout":
"...", "stderr": "...", "truncated": false, "durationMs": n}` with
stdout and stderr each capped at 1 MiB, the head kept and `truncated`
set; a `timeout` expiry ends the command and reports exit code 124.
Once a stream has begun, an error can no longer change the status
code, which is what the error frame and close code 1011 carry.

### The error table

The envelope is `latere.ai/x/pkg/httpjson`'s: `{"error": {"code",
"message", "details"}}`, where `details` always carries `request_id`,
carries `paths` (a list) for a code that names fields, and `detail`
for a developer sentence. `message` is the fixed user sentence below;
`TestErrorTable` asserts one per code and that no handler writes
another.

| `unsupported_media_type` | 415 | Send the manifest as JSON or YAML. |
| `not_acceptable` | 406 | This endpoint answers in JSON or YAML. |
| `multi_document` | 400 | Send one manifest per request. |
| `unsupported_version` | 400 | This server serves cella.latere.ai/v1beta1. |
| `unsupported_kind` | 400 | This server does not serve that kind. |
| `unknown_field` | 400 | The manifest has a field this schema does not know. |
| `missing_field` | 400 | A required field is missing. |
| `invalid_field` | 400 | A field has a value it cannot take. |
| `reserved_prefix` | 400 | That name is reserved for the control plane. |
| `exclusive_fields` | 400 | Two fields that cannot be set together are set. |
| `path_conflict` | 400 | Two mounts share a path. |
| `bad_request` | 400 | The request could not be read. |
| `body_too_large` | 413 | The request body is larger than this server accepts. |
| `unauthenticated` | 401 | Sign in and send a valid token. |
| `forbidden` | 403 | You do not have permission to do this. |
| `not_found` | 404 | There is no such object. |
| `immutable_field` | 409 | This field cannot be changed after the object is created. |
| `boundary_widened` | 409 | A sandbox cannot widen its own boundary. |
| `name_taken` | 409 | You already have an object with this name. |

### Rate limit

After authentication, `CELLA_REQUESTS_PER_MINUTE` per subject, the
authorizer's `limits.requests_per_minute` overriding it, a token
bucket per replica with the limit as the burst; `0` disables. Streams
count once at open. Before authentication, one bucket per client
address of `CELLA_UNAUTHENTICATED_REQUESTS_PER_MINUTE` (default `60`)
bounds a flood of bad tokens. Every response carries
`RateLimit-Limit`, `RateLimit-Remaining`, and `RateLimit-Reset`; a 429
adds `Retry-After`.

### Request id

Every request has one, `req_` plus a ULID. A client's `X-Request-Id`
of at most 128 printable ASCII characters is accepted as is; anything
else is replaced. It is the `request_id` of the envelope, the
`request.id` the authorizer sees, `AdmitRequest.RequestID`, the
event's `request_id`, and the trace's correlation
([[017-observability]]).

### OpenAPI

`tools/apidoc` generates `api/openapi.yaml` from the types of every
kind, the route table, and the error table; the gate fails when the
committed file differs from the generated one, and the server
validates every request against it in the suite so a handler cannot
drift from the document. [[001-architecture]]'s
`TestAPIAndImporterResolveAgree` compares the `PUT` response body with
`Resolve`'s output after stripping `status` from both.
