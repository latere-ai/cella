# API

## Overview

One HTTP surface on the public listener under `/v1`, resource-shaped
around the manifest: apply, read, list, delete, the lifecycle verbs,
and the streams into a sandbox. Every response body is JSON except a
stream. Every error is one envelope with one code. The OpenAPI document
is generated from the Go types and served, so a client generator and
the server agree by construction.

## Current state

Not built. The routes descend from the hosted plane's `/v1`, with the
manifest as the only create body (the legacy create shape is gone) and
the name-addressed apply added.

## Design

### Resources

| Method | Path | Does | Action |
|---|---|---|---|
| `POST` | `/v1/sandboxes` | create from a manifest; 201 with the resolved object; `metadata.name` generated when absent | `sandbox.create` |
| `PUT` | `/v1/sandboxes/{name}` | apply: create when no sandbox of the caller's has that name, else update the mutable fields; 201 or 200 | `create` or `update` |
| `GET` | `/v1/sandboxes` | list, `?label=k=v` repeated, `?phase=`, `?owner=` (admins), paged by `?cursor=` and `?limit=` up to 200 | `sandbox.list` |
| `GET` | `/v1/sandboxes/{id}` | the object with status; `{id}` accepts the name of one of the caller's sandboxes as an alias | `sandbox.read` |
| `DELETE` | `/v1/sandboxes/{id}` | delete; 202 with the object in `Deleting` | `sandbox.delete` |
| `POST` | `/v1/sandboxes/{id}/start`, `/stop` | the lifecycle verbs; 200 with the object | `sandbox.update` |
| `POST` | `/v1/sandboxes/{id}/exec` | run one command; request `{"command": [...], "env": {}, "workdir": "", "tty": false, "timeout": "10m"}`; response a multiplexed stream, or `?wait=1` for a JSON result with the output capped at 1 MiB | `sandbox.exec` |
| `GET` | `/v1/sandboxes/{id}/attach` | a WebSocket carrying a PTY: binary frames are bytes, text frames are `{"resize": {"cols", "rows"}}` | `sandbox.exec` |
| `GET` | `/v1/sandboxes/{id}/files?path=...` | a tar stream of the paths | `sandbox.exec` |
| `PUT` | `/v1/sandboxes/{id}/files?dest=...` | a tar stream extracted under `dest` | `sandbox.exec` |
| `GET` | `/v1/sandboxes/{id}/logs?follow=1` | the sandbox's main process output, newline-delimited | `sandbox.read` |
| `GET` | `/v1/sandboxes/{id}/events` | the events of [[009-events]] for this sandbox, newest first, paged | `sandbox.read` |
| `POST` | `/v1/sandboxes/{id}/token` | mint a workload token for the sandbox, for a caller that runs a process outside the projection | `sandbox.token` |
| `GET` | `/v1/openapi.yaml` | the document, generated | none |
| `GET` | `/.well-known/jwks.json` | the workload token keys | none |

Request bodies for create and apply accept the content types of
[[003-manifest-contract]] and are capped at `CELLA_MAX_BODY_BYTES`.
Every response object is the resolved manifest with `status`, encoded
as JSON with the field order of the schema, or as YAML when the request
says `Accept: application/yaml`.

### The exec stream

Without `?wait=1`, the response is `Content-Type:
application/vnd.cella.exec-stream` with frames of one byte of channel
(`1` stdout, `2` stderr, `3` exit) plus a 4-byte big-endian length plus
the payload; the exit frame carries the code as text and closes the
stream. The request body is stdin until the client half-closes.
`cella exec` speaks this; a shell with `curl` uses `?wait=1`.

### Errors

One envelope, `latere.ai/x/pkg/httpjson`'s:

```json
{"error": {"code": "immutable_field", "message": "This field cannot be changed after the sandbox is created.", "detail": "spec.image", "request_id": "req_..."}}
```

`message` is one fixed user sentence per code; `detail` is the
developer's. Codes and statuses:

| Status | Codes |
|---|---|
| 400 | `unsupported_media_type`, `multi_document`, `unsupported_version`, `unsupported_kind`, `unknown_field`, `missing_field`, `invalid_field`, `reserved_prefix`, `exclusive_fields`, `body_too_large`, `bad_request` |
| 401 | `unauthenticated` |
| 403 | `forbidden` |
| 404 | `not_found` |
| 409 | `immutable_field`, `name_taken`, `phase_conflict`, `tier_ephemeral` |
| 422 | `ceiling_exceeded`, `capability_unsupported`, `admission_refused`, `quota_exceeded` |
| 429 | `rate_limited`, with `RateLimit-Limit` and `RateLimit-Remaining` on every response |
| 503 | `authorizer_unavailable`, `admission_unavailable`, `backend_unavailable` |

Every response carries `X-Request-Id`, and the same value is the
`request_id` of the error and the `request.id` the authorizer saw.

### Rate limit

`CELLA_REQUESTS_PER_MINUTE` per subject, the authorizer's
`limits.requests_per_minute` overriding it, a token bucket with the
limit as the burst. Streams count once at open.

### OpenAPI

`tools/apidoc` generates `api/openapi.yaml` from the manifest types,
the route table, and the error table; the gate fails when the committed
file differs from the generated one, and the server validates every
request against it in the suite so a handler cannot drift from the
document.

## Acceptance criteria

| Criterion | Test that proves it | State |
|---|---|---|
| Every route in the table exists, requires a bearer, and asks the authorizer the action in its row | `TestRouteTableActions` against the stub authorizer | not built |
| `PUT` twice with the same manifest is 201 then 200 and the object is unchanged | `TestApplyIsIdempotent` | not built |
| A `PUT` changing `spec.image` is 409 `immutable_field` with the path in `detail` | `TestApplyRefusesImmutableChange` | not built |
| Every error code in the table maps to its status and has one fixed `message` | `TestErrorTable` | not built |
| The exec stream carries a 64 MiB stdout without buffering and ends with the exit frame | `TestExecStreamFraming` | not built |
| Attach carries bytes both ways and a resize frame reaches the PTY | `TestAttachRoundTrip` | not built |
| The committed OpenAPI document equals the generated one and every request in the suite validates against it | `TestOpenAPIIsCurrent`, the validating middleware in test mode | not built |
| The 601st request in a minute from one subject is 429 with the headers | `TestRateLimit` | not built |
